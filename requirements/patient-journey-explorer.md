# patient-journey-explorer requirements matrix

> Source-backed requirement matrix for the safety.viz **patient-journey-explorer** (Patient Journey Explorer) module — a single-subject, multi-domain longitudinal view: one participant's exposure, dose changes, adverse events, labs, con-meds, medical history and disposition as stacked lanes on one shared study-day axis, with time anchorable on any event and a mechanical (no-AI) context panel ([safety.viz#142](https://github.com/jwildfire/safety.viz/issues/142); parent requirement [obot.roadmap#349](https://github.com/jwildfire/obot.roadmap/issues/349); R widget follow-on [obot.roadmap#350](https://github.com/jwildfire/obot.roadmap/issues/350)). Requirement IDs use the module's condensed `PJE-*` scheme cited in the source JSDoc, the tests, and [`docs/patient-journey-explorer-coverage.md`](https://github.com/jwildfire/safety.viz/blob/main/docs/patient-journey-explorer-coverage.md). IDs are the **base** form so each row resolves the matching `requirementIds` tag in the shipped `docs/evidence/patient-journey-explorer/evidence.json`, which the evidence pages look up by exact ID. The area token is letters only (`ACC`, never `A11Y`) because the extractor's ID grammar admits no digits in the area — the `HEP-ACC-*` precedent. The `Evidence Type` column routes rows: `unit` → Vitest (`tests/unit/patient-journey-explorer/`), `browser` → Playwright (`tests/e2e/patient-journey-explorer.spec.js`, plus `tests/e2e/site.spec.js` for the two demo-page rows); where a row is covered by both suites the browser evidence is listed. Treat this as a reviewed starting matrix: the rows are AI-reviewed **in an unattended session** and awaiting human sign-off — the design decisions D1–D30 are adopted provisionally (D4, D16, D23 and D24 were confirmed by @jwildfire in-session on 2026-09-18), and the module ships marked **Experimental** until his review.

## Requirement context

- Requirement: [obot.roadmap#349](https://github.com/jwildfire/obot.roadmap/issues/349) — the Patient Journey Explorer: one participant's whole safety course on one study-day axis
- Implementation: [safety.viz#142](https://github.com/jwildfire/safety.viz/issues/142) (milestone v1.8.0)
- Follow-on (out of scope here): [obot.roadmap#350](https://github.com/jwildfire/obot.roadmap/issues/350) — `Widget_PatientJourneyExplorer()` in gsm.safety. The `width` / `height` settings and the `resize()` method exist for it; nothing else in this matrix anticipates it.
- Out of scope by design (§1): LLM narratives and "why" summaries, cohort similarity, cross-study aggregation, PHI handling, unblinding, auth or any backend; a repo-wide dark-mode toggle (dark tokens are declared, no toggle is added); a QT/ECG lane; cross-subject comparison of any kind; a version bump (`dist/` rebuilds at 1.7.0 and the module lands under `v1.8.0 (Upcoming)`).

## Scope

**This matrix:** one renderer consuming up to six domains — exposure (EX), adverse events (AE), labs (LB), con-meds (CM), medical history (MH) and disposition (DS) — in either of two input forms (a merged array carrying a domain column, or an object of per-domain arrays), normalized to one internal model with per-domain counted, reasoned, CSV-exportable dropped rows. Seven lanes on one shared, linear study-day axis (exposure, dose changes, adverse events, labs as one small multiple per test, con-meds, medical history, disposition), collapsible lane groups, per-lane toggles and three filters. Anchoring on any placeable mark: the axis relabels to days from the anchor, a ±N-day context window is highlighted, out-of-window marks de-emphasize, and a side panel lists — mechanically — the con-meds active at the anchor, the abnormal labs in the window, the dose changes in the window and the prior adverse events with the same preferred term, every item linking back to the raw row the host passed to `init`. Study-day ↔ calendar-date display. Keyboard navigation over every mark with a visible focus ring and a polite live region; WCAG AA contrast in light mode with dark tokens pre-declared. An event surface (settings callbacks, instance listeners and a DOM `CustomEvent`) carrying the whole context bundle so a later AI layer never reads the DOM.

**The organizing principle is honesty about what the data does and does not say** (design §5.1, §5.6–5.7, D8, D16): a con-med with no start day is not asserted active; a record with no end day is "ongoing" only when its outcome column says so and is otherwise "end not recorded" — still counted and still drawn, but labelled as such wherever it is counted; every arithmetic step runs in a continuous elapsed-day space so a ±30-day window spans 30 days on each side and "days from anchor" agrees with the calendar; and the panel's standing sentence says co-occurrence is not causation.
