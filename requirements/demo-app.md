# demo app requirements matrix

> Requirement matrix for the safety.viz **demo app**: a full-page web app, served at `demo/` on the site and as one HTML file, that loads a user's own files in the browser, maps them to the standard domain set, and draws the charts their data supports. Not a renderer: it hosts the renderers. Requirement IDs use the prefix **APP** with these areas: **PARSE** (file text to rows), **PLACE** (which domain a file is), **MAP** (the pre-filled mapping), **STAT** (chart status), **CHART** (the per-chart recipes that turn a mapping into settings and data), **PAGE** (the page and its chart list), **LOAD** (the data panel: loading files, correcting the mapping, saving it), **FILE** (the single-file build), **LIB** (further chart libraries beside safety.viz's own), **BIO** (bio.viz's biomarker charts, carried in the demo page and the single file), **R** (R on request for the biomarker charts), **LOCAL** (the demo page run on a reader's own machine: the installer, `npm run demo` and its server), **WF** (the gsm pipeline's workflow files, copied from their packages' release tags for R in the browser).

## Requirement context

- Requirement: [obot.roadmap#352](https://github.com/jwildfire/obot.roadmap/issues/352) — the basic app: load, map and view a study on one page, and as one file. Design: [352_design.html](https://jwildfire.github.io/obot.roadmap/requirements/design/352_design.html).
- Implementation, in order: the app core ([safety.viz#149](https://github.com/jwildfire/safety.viz/issues/149)), the portfolio page on the demo study ([#150](https://github.com/jwildfire/safety.viz/issues/150)), the data panel ([#151](https://github.com/jwildfire/safety.viz/issues/151)), the single-file build ([#152](https://github.com/jwildfire/safety.viz/issues/152)), the data view's sidebar, reset and demo studies ([#159](https://github.com/jwildfire/safety.viz/issues/159)), the mapping step's state and following the address ([#163](https://github.com/jwildfire/safety.viz/issues/163)), the release review's fixes, self-hosted typefaces and the Patient Journey Explorer leaving the app ([#165](https://github.com/jwildfire/safety.viz/issues/165)), a second chart library beside safety.viz's own ([#181](https://github.com/jwildfire/safety.viz/issues/181), requirement [obot.roadmap#366](https://github.com/jwildfire/obot.roadmap/issues/366)), bio.viz's biomarker charts carried in the demo page and the single file ([#182](https://github.com/jwildfire/safety.viz/issues/182)), R on request for them in the hosted app ([#183](https://github.com/jwildfire/safety.viz/issues/183)), the demo page installed and run on a reader's own machine ([#214](https://github.com/jwildfire/safety.viz/issues/214)), and the app rebuilt on bio.viz's and gsm.bio's later work, the group comparison's three levels and the cross-tabulation ([#212](https://github.com/jwildfire/safety.viz/issues/212), requirement [obot.roadmap#367](https://github.com/jwildfire/obot.roadmap/issues/367)), and a footnote under each chart linking its clinical guide and test evidence ([#246](https://github.com/jwildfire/safety.viz/issues/246)). Toward the gsm pipeline run in the browser (requirement [obot.roadmap#373](https://github.com/jwildfire/obot.roadmap/issues/373)): its workflow files, copied from the packages' release tags ([#230](https://github.com/jwildfire/safety.viz/issues/230)).
- Depends on the portfolio manifest, `src/data/portfolio.json` ([safety.viz#138](https://github.com/jwildfire/safety.viz/issues/138), requirement [obot.roadmap#325](https://github.com/jwildfire/obot.roadmap/issues/325)): the standard domain set and what each chart reads from it.
- Lineage: the old safetyGraphics Shiny app's data loader, standard detection, mapping tab and chart-availability check.

## Scope

**This matrix** covers the thin vertical slice the basic app requirement describes. What it leaves to the requirements that widen it: one set of filters across every chart and the study configuration (obot.roadmap#327); detecting the standard as well as the domain (obot.roadmap#333); field-by-field validation of values (obot.roadmap#334); the participant drill-down following the mapped identifier across charts (obot.roadmap#335); an inlined demo study and a size budget for the single file (obot.roadmap#336).

**Two rules shape every row.** A guess is always labelled as a guess, and nothing fuzzier than a same-name or known-alternative match is attempted (design D2). A gap is priced in the charts it turns off, by name, never in a count of empty boxes.
