# portfolio app requirements matrix

> Requirement matrix for the safety.viz **portfolio app**: one page that loads a user's own files in the browser, maps them to the standard domain set, and draws the charts their data supports. Not a renderer: it hosts the renderers. Requirement IDs use the prefix **APP** with these areas: **PARSE** (file text to rows), **PLACE** (which domain a file is), **MAP** (the pre-filled mapping), **STAT** (chart status), **PAGE** (the page on the demo study), **LOAD** (the data panel), **FILE** (the single-file build).

## Requirement context

- Requirement: [obot.roadmap#352](https://github.com/jwildfire/obot.roadmap/issues/352) — the basic app: load, map and view a study on one page, and as one file. Design: [352_design.html](https://jwildfire.github.io/obot.roadmap/requirements/design/352_design.html).
- Implementation, in order: the app core ([safety.viz#149](https://github.com/jwildfire/safety.viz/issues/149)), the portfolio page on the demo study ([#150](https://github.com/jwildfire/safety.viz/issues/150)), the data panel ([#151](https://github.com/jwildfire/safety.viz/issues/151)), the single-file build ([#152](https://github.com/jwildfire/safety.viz/issues/152)).
- Depends on the portfolio manifest, `src/data/portfolio.json` ([safety.viz#138](https://github.com/jwildfire/safety.viz/issues/138), requirement [obot.roadmap#325](https://github.com/jwildfire/obot.roadmap/issues/325)): the standard domain set and what each chart reads from it.
- Lineage: the old safetyGraphics Shiny app's data loader, standard detection, mapping tab and chart-availability check.

## Scope

**This matrix** covers the thin vertical slice the basic app requirement describes. What it leaves to the requirements that widen it: one set of filters across every chart and the study configuration (obot.roadmap#327); detecting the standard as well as the domain (obot.roadmap#333); field-by-field validation of values (obot.roadmap#334); the participant drill-down following the mapped identifier across charts (obot.roadmap#335); an inlined demo study and a size budget for the single file (obot.roadmap#336).

**Two rules shape every row.** A guess is always labelled as a guess, and nothing fuzzier than a same-name or known-alternative match is attempted (design D2). A gap is priced in the charts it turns off, by name, never in a count of empty boxes.
