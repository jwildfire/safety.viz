Standard domain set

The standard domain set is the 4 tables a study supplies to safety.viz. Their column names are the ADaM-shaped defaults the charts already expect, so data in this shape feeds all 18 charts without renaming a column, and a column under another name is mapped through that chart's settings.

Domains
Subject-level, Adverse events, Labs and vitals, ECG

What each chart needs

Each setting names the column a chart reads for one purpose, and defaults to the column shown. Required marks the settings the chart's own data schema lists as required; the rest are optional. A setting shown with no default reads no column until one is named, and the chart's API reference says what each setting does.

The manifest's format

The manifest is written in format version 2. Version 2 lets a second chart library publish its own chart list in the same format, so the demo app can list its charts beside these, read from the same files through the same mapping. A library's chart list may leave out the domains: its charts read this standard set. The charts on this page use none of the fields version 2 adds, and each means what it meant in version 1. What a chart entry can say besides its domains and settings:

  • library names the chart library the chart comes from. Left out, it is safety.viz.
  • group names the group the chart is listed under: a standard domain, or one of the manifest's groups, each with the label on its tab and an order among such groups, which come after the domains. Left out, a chart is listed under the first domain it reads.
  • tables names the tables the chart's init takes when it takes several, each read from one standard domain and marked required or not. The chart is handed an object of those tables built from the loaded files, and an optional table with no file is left out of it.
  • unmappedSettings says what the chart is handed for a setting with nothing mapped: "null", no column, as when it is left out; or "omit", nothing at all, for a chart that refuses a null column setting.
