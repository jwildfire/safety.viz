# safety.viz v1.8.0 (Upcoming)

**See it move:** the [annotated v1.8.0 demo](https://jwildfire.github.io/obot.roadmap/reports/sv-v1.8-demo/) walks the demo app, the Patient Journey Explorer prototype and the changes to the existing charts, with captures and try-it-yourself steps against the live site.

safety.viz becomes something you can use on your own study. A demo app puts every chart on one study, tells you which ones your data can feed, and lets you load your own files and map their columns, all in the browser. Nine long-standing requests from the people who used the original renderers land across the existing charts. And a prototype of a fourteenth chart, the Patient Journey Explorer, follows one participant across exposure, events, labs and medications, and can draft a narrative of what the record shows; a prototype is not ready for production, so it is on the docs site only and is not counted a finished chart. No existing API is removed or renamed; two existing behaviours change, and are listed under Changed.

## What's new

### The demo app

- **The demo app lists thirteen charts by the data they read, says which the loaded study supports, and draws the one you choose** ([obot.roadmap#352](https://github.com/jwildfire/obot.roadmap/issues/352), [#149](https://github.com/jwildfire/safety.viz/issues/149), [#150](https://github.com/jwildfire/safety.viz/issues/150)). The original safetyGraphics app put a study’s charts in one place and told you which ones your data could feed; this starts that app again, as a web app of its own at [demo/](https://jwildfire.github.io/safety.viz/demo/), beside the docs site and its per-chart demos. Open Demo app from the site’s navigation, where it is the first entry, bordered and with an arrow ([#172](https://github.com/jwildfire/safety.viz/issues/172)). Its own parts are a header and a footer, so the chart has the full width of the page. The header has a tab for your data and a tab for each domain — labs and vitals, ECG, adverse events — saying how many of that domain’s charts the data supports; beneath them, on one line, are that domain’s charts, the open one highlighted, each with a small hex: the domain’s colour when the chart is ready, red when something it needs is missing, hollow when it has no file to read. On the demo study all thirteen read “ready”. The Patient Journey Explorer, a prototype, is not in the app. A chart that is not ready says what it is missing by name — the column, the measure or the file — and a chart that was ready but fails on load says so with its own message, and its domain’s count drops. One chart is drawn at a time, and the address names it: a link to a chart, or to `#data`, opens that view, and the browser’s back and forward move between them ([#163](https://github.com/jwildfire/safety.viz/issues/163)). The participant profile is listed with a status and opens, as before, beside the chart you select a participant in. On a phone the tabs and the charts scroll within their rows.

- **Load your own study: drop CSV or JSON files on the app, correct what it guessed, and the charts redraw from your data** ([#151](https://github.com/jwildfire/safety.viz/issues/151), [#159](https://github.com/jwildfire/safety.viz/issues/159), [#165](https://github.com/jwildfire/safety.viz/issues/165)). The Data view reads each file in the browser — nothing is uploaded, the hosted app serves its own typefaces rather than fetching them from another host, and a test asserts that no request leaves the page once a file is chosen — and places it in a domain by its column names, saying how many of that domain’s columns it found. Labs and ECG files have the same shape, so where a file could be either its measure names decide: a QTc correction among them makes it ECG, anything else labs. Under each file is one table: what the charts need on the left, your column on the right. A row filled because the name matched says “same name”; a row filled from a short list of known SDTM and ADaM alternatives says “guessed”; nothing fuzzier is attempted, and a row you set yourself says “chosen”. An empty row says which charts need it, and a row you clear is read by no chart. The same table asks what your data calls the handful of measures some charts find by name — ALT, AST, total bilirubin, alkaline phosphatase, creatinine, the QTc corrections and heart rate. A bracketed unit in a measure’s name is ignored when matching and any other bracketed text is not, so “Bilirubin (Direct)” is never guessed as total bilirubin. Change a row and every chart’s status updates at once. Each domain holds one file: a second file of the same type takes its place, and the first is kept on the page, set aside, with a sentence saying which replaced which — it is never dropped. (Labs and vitals delivered as separate files are not combined yet.) Loading files of your own clears a demo study. A file that fits no domain is reported in one sentence and can be placed by hand; a file over 100 MB, or one that is not CSV or JSON, is refused in a sentence. The mapping downloads as a small JSON file, and choosing that file again with your data restores it. Your data is never renamed or rewritten: a mapping only tells each chart which of your columns to read. A sidebar on the Data view keeps the work in sight: three steps — load your files, check the mapping, open a chart — each showing where it stands and carrying its own buttons, so the file picker and Reset sit with loading, the count of guessed rows and of rows a chart is waiting on sits with Download mapping (the step is done once no chart is waiting on a row; guesses stay counted and flagged), and the count of charts that are ready sits with a button that opens the first of them. Under the steps is the list of loaded files, each flagged only when a row wants a look; choose one to jump to its table. Reset clears every file and mapping and returns to the empty drop zone. The hosted app also offers three demo studies by name: the pilot study, where every column maps itself; a renamed-column study, where six rows need setting by hand; and a labs-only liver cohort, which shows what the app says when the other domains have no file. Each says in a sentence what is in it — including that the pilot study’s labs file carries 110 synthetic liver and kidney participants who are in no other file. Chart views have no sidebar, so a chart still has the full width.

- **The same app as one file you can take with you** ([#152](https://github.com/jwildfire/safety.viz/issues/152)). The app’s footer offers a single HTML file, under 1 MB, that holds every chart and the loader. Save it, open it from your disk — no install, no server, no network — and drop your study’s files on it. It starts empty: it carries no demo data, and it uses your system’s fonts. A test opens the built file with the browser offline, loads a study, corrects its mapping and draws every chart.

### A prototype

- **Patient Journey Explorer** — a new renderer, and the first in the gallery that looks at one participant rather than across them ([obot.roadmap#349](https://github.com/jwildfire/obot.roadmap/issues/349), [#142](https://github.com/jwildfire/safety.viz/issues/142)). Pick a participant and their whole safety record draws on one shared study-day axis as stacked lanes: exposure with its dose changes, adverse events, one lab sparkline per test with its reference band, con-meds, medical history and disposition. **Click any event to anchor time on it**: the axis relabels to days from the anchor, a ±30-day context window is highlighted, and a side panel lists — mechanically, with no interpretation — the con-meds active at that moment, the abnormal labs in the window with their ratio to the limit they crossed, the dose changes in the window, and every earlier adverse event with the same preferred term. Every mark and every panel item jumps to the raw source row it came from. The panel says what the data does not support as plainly as what it does: a con-med with no start day is never asserted active, a record with no end date is shown as active but labelled "end not recorded" rather than "ongoing", and a standing sentence says that co-occurrence is not causation. Offsets are counted in elapsed days, so a ±30-day window is 30 days on each side even across first dose. Every mark is keyboard-reachable with a spoken name and a visible focus ring. Feed it either an object of per-domain arrays or one merged array with a domain column; a host can subscribe to the whole context bundle through callbacks, listeners or a DOM event without reading the page. Ships as a **Prototype**, not ready for production and not counted a finished chart: the review of this release found five cases where it misdraws or drops part of a record — a record far to the left of the axis, dose changes across two concurrent treatments, a lab test spelled in two cases, an end day of zero, and nested settings ([#167](https://github.com/jwildfire/safety.viz/issues/167)). Until those are closed it is on the docs site only, outside the demo app and the standard domain set; the R widget follows under [obot.roadmap#350](https://github.com/jwildfire/obot.roadmap/issues/350). [Try it live](https://jwildfire.github.io/safety.viz/patient-journey-explorer/index.html).

- **AI narratives on the Patient Journey Explorer** — the chart can now write down what the record shows, in sentences you can check ([obot.roadmap#351](https://github.com/jwildfire/obot.roadmap/issues/351), [#146](https://github.com/jwildfire/safety.viz/issues/146)). Open a participant and a short summary of their whole course sits above the lanes; anchor an event and a paragraph on what surrounded it appears at the top of the context panel; ask, from the tray beneath the lanes, and you get one for a lab test, for the dose course, or for disposition — five kinds in all. **Every draft is written from the same rows the panel lists, and every sentence carries the rows it came from as clickable chips**: click one and the mark it names lights up on the timeline, or opens its source record when it is not currently drawn. The model is handed those rows through read-only queries and nothing else — no document search, no free text — so the numbers in a narrative are the numbers the chart derived, not numbers a model worked out. **Every sentence is stamped `Draft — AI generated` until a reviewer accepts it, and the chart never accepts anything itself**: Accept, Reject, Edit and Regenerate are reported to the host application, which decides what accepting means and where the text goes. Nothing is published, stored or sent anywhere by the chart. A validator sits between the model and the page and rejects the language this tool has no business using — causal wording, named diagnoses, treatment advice, prognosis, claims of certainty, and anything describing the person rather than the record — drops any sentence citing a row it was not shown, and turns "nothing to say" into a card that says why rather than an empty space. Change the window and the event card is drafted again for the new window; change a filter that moves the rows a card was drafted from and the card greys, says so, and offers Regenerate; change the participant and every card clears. It is provider-agnostic behind one interface — Claude first, OpenAI, and a deterministic offline adapter that drafts from the real rows — and a 30-case evaluation set across the five narrative kinds, scored for faithfulness, coverage, hallucination, style and correct refusals, runs against that offline adapter as a CI gate, so a prompt change that starts saying more than the rows support fails the build. Ships as part of the **Prototype** and off by default: a host that binds no narrative supplies gets the mechanical chart unchanged. The review of this release found seven defects in this layer, among them that a draft can cite another participant’s rows and pass validation, and that a draft made from data that has since changed is not always marked stale ([#168](https://github.com/jwildfire/safety.viz/issues/168)); treat its drafts as a demonstration, not as text to rely on. On the demo the narratives work with no key at all, and a toggle runs them through Claude with your own key, kept in your browser tab and sent straight to the API. [Try it live](https://jwildfire.github.io/safety.viz/patient-journey-explorer/index.html).

### Asked for by the people who used the original renderers

When the RhoInc and SafetyGraphics safety renderers were retired they left 282 open issues behind — years of requests from the clinicians, programmers and reviewers who actually ran these charts on studies. A [survey of all twelve trackers](https://jwildfire.github.io/obot.roadmap/reports/legacy-tracker-migration-2026-08-24/) found 144 of them still worth carrying into safety.viz, and picked out nine that the shared modules make cheap. Those nine are in this release: the eight below and the fix under Fixed. Every item names the issue it answers and, where the tracker recorded one, the person who filed it.

- **A filter means the same thing in every chart — `start`, `all` and `multiple`.** You can now say what value a filter opens on, whether it offers an "All" option at all, and whether it accepts more than one value at once — and it works identically in all twelve renderers that have a filter, held there by one test that runs the same cases against every one of them ([#166](https://github.com/jwildfire/safety.viz/issues/166)). `start` only sets what the filter opens on: "All" stays on offer unless you pass `all: false`. The dropdown always shows what the chart is filtered by: with `all: false` and no start the first value is selected, and a start value the data does not contain is reported in the console and the filter opens on All. Multi-value filters are new everywhere: pick three treatment arms, or four system organ classes, and the chart shows the union. This was filed against six of the original renderers by their own maintainer, samussiah, in 2021 ([ae-timelines#83](https://github.com/RhoInc/ae-timelines/issues/83) and five siblings): _"webcharts supports start/all/multiple but the filters in most of the safety explorer modules are hard coded with only the value_col and label properties - even if other properties are specified."_ Five years on it was still true of the port. Filters that declare only a column and a label behave exactly as before.

- **You choose which measures the Measure control offers, and in what order.** A new `measures` setting is an ordered whitelist: list the measures a study cares about and the dropdown offers exactly those, in exactly that order, instead of every measure in the data alphabetically. It lands in the Safety Histogram, Outlier Explorer, Results Over Time, Shift Plot and Delta-Delta at once. Four of the trackers asked to subset that dropdown, starting in 2016 ([safety-results-over-time#5](https://github.com/RhoInc/safety-results-over-time/issues/5)); five more asked to order it by something other than the alphabet in 2021 — brittsikora on safety-delta-delta#38 put it as _"Need to apply measure order in small multiples."_ One setting answers both. For the Delta-Delta plot the list also decides which comparison the chart opens on. Leave it unset and nothing changes.

- **A Reset control on nine charts.** Every renderer with a control panel now carries a "Reset chart" button at the foot of it: filters, measures, visits, scales, display choices, selections and linked listings all return to how the chart opened. Nine issues across seven trackers asked for this, most of them filed on a single day in December 2017 ([safety-histogram#61](https://github.com/RhoInc/safety-histogram/issues/61) and siblings). Until now the library offered "Reset Limits", which resets an axis and nothing else. Where a default is derived from the data rather than configured — the opening measure, the baseline and comparison visits — reset re-derives it rather than blanking it.

- **The Adverse Event Explorer says what kind of empty an empty table is.** "No AEs found for the current filters" used to cover several different situations. It now distinguishes between no participants matching the current selection — naming how many participants the data holds — participants who simply have no adverse events recorded, and events removed by the active event filters. Only the last reads as an error; an event-free study is reported in neutral text, because it is a finding, not a fault. Asked for by pburnsdata on [aeexplorer#153](https://github.com/RhoInc/aeexplorer/issues/153): _"Currently can't distinguish between the absence of AES and the absence of subjects."_

- **The Shift Plot learns a log scale.** A new Axis Type control switches between linear and logarithmic. On a wide-range measure such as Alkaline Phosphatase the points stop piling into the bottom-left corner and spread out where you can read them. Both axes share one domain — that is what keeps the dashed identity line meaning "no change" — so the choice applies to the pair. A participant whose baseline or comparison value is zero or negative cannot sit on a log axis at all, so that pair is removed and **counted in the note above the chart**, never clamped and never quietly dropped. This answers the oldest request in the whole sweep: brittsikora, April 2016, [safety-shift-plot#3](https://github.com/RhoInc/safety-shift-plot/issues/3) — _"Auto-scaling was throwing people off, so add ability to set limits. Or toggle between log axis and linear."_ The axis-limits half of that request is filed separately.

- **The QT Explorer prints the confidence intervals it was only drawing.** Beneath the central-tendency chart, a by-arm table now gives each visit's sample size, the plotted mean or median change, and the lower and upper bounds of the interval the band shades. Replicate readings, such as triplicate ECGs, are averaged to one value per participant and visit before anything is computed, so the sample size counts participants. It follows the current selection: switch to placebo-corrected ΔΔ and the table drops placebo and prints the corrected difference; change the correction or a filter and the numbers move with the chart, because the table is built from the same series the chart is. Asked for on [qtexplorer#41](https://github.com/SafetyGraphics/qtexplorer/issues/41).

- **The QT Explorer carries its safety language permanently.** A standing caution — exploratory tool, not validated for clinical use, confirm any signal with the validated ICH-E14 analyses — is now mounted into the chart itself and shown in every view. A similar sentence previously lived in each view's footnote, where it disappeared whenever the footnote was cleared, including when you selected Heart Rate on the outlier or categorical views. And when the data carries more than one treatment arm, a second warning appears: every view colours and labels participants by arm, so it asks you to confirm the view is permitted by the study's blinding plan. A single-arm or pooled extract raises no such warning. Asked for by the QT reviewers a year apart, on [qtexplorer#51](https://github.com/SafetyGraphics/qtexplorer/issues/51) and [#52](https://github.com/SafetyGraphics/qtexplorer/issues/52).

- **The Hepatic Safety Explorer knows about unscheduled visits.** A new "Unscheduled visits" checkbox — shown only when the mapped visit column actually contains one — includes or excludes records taken at an unscheduled visit. Unlike the equivalent in Results Over Time, this is not a display toggle: excluding a record re-derives that participant's baseline and on-treatment peak, so the chart changes underneath you. On the shipped demo data, 792 of 56,266 records sit at unscheduled visits, 429 resolved baselines move when they are excluded, and 53 participant-measure series disappear entirely. **They are therefore included by default**, which is exactly today's behaviour: an unscheduled draw in a hepatic study is very often the draw a suspected injury prompted, and hiding it by default would hide the peak that caused the visit. The count of excluded records appears in the note above the chart, in every view that applies the exclusion. Asked for on [hep-explorer#229](https://github.com/SafetyGraphics/hep-explorer/issues/229) in 2019: _"We can probably use the same approach and settings established in other renderers."_

## Changed

Two things an existing page may notice. Both follow from making one rule hold in every chart ([#166](https://github.com/jwildfire/safety.viz/issues/166)).

- **A filter with a `start` value keeps its "All" option, in every chart.** Before this release the two charts that read `start` disagreed: the Outlier Explorer dropped "All" when a start value was given, and the Adverse Event Explorer kept it. Now a start value only sets where the filter opens, everywhere; pass `all: false` to remove "All". On the Outlier Explorer that adds an option where there was none; the chart still opens on the start value. A start value the data does not contain now opens the filter on All, with a console warning, rather than drawing an empty chart.
- **The QT Explorer averages replicate readings before it computes anything.** With more than one reading per participant and visit — triplicate ECGs — the central-tendency chart and its table used to count every reading as a participant, which overstated the sample size and narrowed the confidence interval. Readings are now averaged to one value per participant and visit first, and n is the number of participants. Data with one reading per participant and visit, including the demo data, gives the same numbers as before.

## Fixed

- **The Adverse Event Explorer drew no counts at all for a single-arm study with the per-group columns switched off.** With `group_cols: false` and `total_col: true` — a configuration the requirements document explicitly — a study with one treatment arm rendered a table with a Category column, a dot plot, and no numbers anywhere. The Total column was being suppressed on the assumption that the single group's own column was carrying the counts, which is false when there are no group columns. Reported on [aeexplorer#148](https://github.com/RhoInc/aeexplorer/issues/148) in 2020 and inherited by the port. This is the one item in the sweep that was a live defect rather than a missing feature.

- **Text from a dataset is written to the page as text.** The Nephrotoxicity Explorer wrote a unit value into its stage summary as markup, the "Required variable(s) missing" message did the same with column names in every chart, and the Hepatic Safety Explorer’s migration notes with arm names — so markup in a dataset could be run by the page that displayed it. All are now written as text, and a test holds every chart to it ([#166](https://github.com/jwildfire/safety.viz/issues/166)).

## What's new

- **Time-to-Event Explorer** — a new renderer for Kaplan–Meier safety displays ([obot.roadmap#161](https://github.com/jwildfire/obot.roadmap/issues/161), [#128](https://github.com/jwildfire/safety.viz/issues/128), PRs [#129](https://github.com/jwildfire/safety.viz/pull/129) and the sv#131 review rework). **You compose the endpoint yourself, from the event data**: flexible multiselect filters over the adverse events (body system, preferred term, seriousness, severity — configurable per study) define what counts as a qualifying event, and the chart shows time to each participant's first qualifying event, censored at end of follow-up from the population data. No endpoint list is hard-coded — the important events vary from study to study; configured one-click presets are a natural later release on the same filter state. Step curves by treatment group with censoring tick marks, **pointwise 95% confidence bands** (the `survival::survfit` default family, cross-validated against it), and the **at-risk / cumulative-events strip table** — all derived from one estimator pass, so the table cannot disagree with the curve, and drawn without intro animation so every frame the chart shows is an estimate, never a transition. It consumes ADAE-shaped event records plus an ADSL-shaped population extract, defaults to **cumulative incidence (1 − KM)** with the estimator always named on the axis, and states plainly — in-app and in the clinical guide — the fixed derivation rule and where that estimator overreads risk. Ships **Experimental** pending the external clinical review above, and pending review of the design decisions. [Try it live](https://jwildfire.github.io/safety.viz/time-to-event/index.html).

## What's new

- **Nephrotoxicity Explorer** — a new renderer for KDIGO acute-kidney-injury screening ([obot.roadmap#35](https://github.com/jwildfire/obot.roadmap/issues/35), [#120](https://github.com/jwildfire/safety.viz/issues/120), PR [#121](https://github.com/jwildfire/safety.viz/pull/121)). One point per participant at their maximum post-baseline **fold change** in serum creatinine against their maximum **absolute change**, over the L-shaped KDIGO stage zones — the fold bands at any absolute change, plus the ≥ 0.3 mg/dL arm below 1.5× — with the lower-left box, where both criteria are clear, left unpainted. The **≥ 4.0 mg/dL Stage-3 rule is a mark, not a zone**: a larger triangular point with its own tooltip line, so a high-baseline chronic-kidney-disease participant sitting in the Stage-1 band is still read as Stage 3 and says why. Units resolve per record (mg/dL and µmol/L can mix within one participant); a record that resolves to neither suppresses absolute-change staging chart-wide rather than guessing. Nothing is dropped silently — participants whose creatinine only fell stay on the chart below zero, and every dropped record and participant downloads as a CSV naming its reason. The stage summary table counts the population three ways, with **dashes, not zeroes**, where KDIGO defines no stage on absolute change. Marked **Experimental** pending clinical confirmation of the staging ladder. [Try it live](https://jwildfire.github.io/safety.viz/nep-explorer/index.html).

- **Study-day playback with motion trails** on the Hepatic Safety Explorer ([obot.roadmap#88](https://github.com/jwildfire/obot.roadmap/issues/88), [#46](https://github.com/jwildfire/safety.viz/issues/46), PRs [#118](https://github.com/jwildfire/safety.viz/pull/118), [#119](https://github.com/jwildfire/safety.viz/pull/119)). Press play and the eDISH cloud walks each participant along their own lab trajectory, motion trails accumulating behind the moving points; scrub the day slider and the playback yields to you rather than fighting for the day. The original's four drawing rules are ported verbatim: a point sits on its most recent result at or before the shown day, holds at its first result before it is measured, shrinks outside its own measured span, and is not drawn before its first record.

- **An opt-in P_ALT hepatocyte-loss estimate** (same requirement, [#49](https://github.com/jwildfire/safety.viz/issues/49) partial, PR [#118](https://github.com/jwildfire/safety.viz/pull/118)). With `calculate_palt: true`, the participant profile header shows the estimated fraction of hepatocytes lost, with the arithmetic behind it. Off by default on purpose: the estimate integrates ALT over study day × 24 hours and carries unit and sampling assumptions only the data owner can confirm.

- **The eDISH axes finish their v1.2 polish list** ([#54](https://github.com/jwildfire/safety.viz/issues/54), PR [#122](https://github.com/jwildfire/safety.viz/pull/122)). On log axes a **Log Base** picker chooses decades or doublings — a tick generator, not a transform, so the cloud never moves, only the gridlines. **Manual axis limits** on both axes load pre-filled with the limit actually in force; clear one to hand that side back to auto, and a limit typed for one measure never survives to another. The drill-down labs chart **names each measure in full** in its legend and writes each line's short key at its own last point. The Clinical guide links the R / nR primary sources and states the nR formula.
